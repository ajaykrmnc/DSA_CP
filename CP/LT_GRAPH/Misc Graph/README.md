# Misc Graph

Use this section for graph-adjacent problems that do not cleanly fit traversal, shortest paths, DSU, MST, tree, or DP patterns yet.

## When To Use

- The solution models relationships as a graph, but the main trick is construction, parity, greedy ordering, permutation cycles, or casework.
- The problem has graph language but the actual answer comes from degree counts, local constraints, or simple structural observations.
- You are unsure where a note belongs and want to keep it inside graph notes until a clearer pattern appears.
- The pattern appears only once or twice and does not deserve a dedicated subsection yet.

## First Choice

- First check if the task can be reclassified into a stronger pattern: traversal, DSU, shortest path, bipartite, tree, or graph DP.
- If not, write the note around the invariant or observation that solves the problem.
- Add a "move later" hint in the note when a repeated pattern starts forming.

## Do Not Use This Section When

- The same idea appears in multiple problems: promote it into its own subsection.
- The problem has a standard graph algorithm name: place it in that algorithm's folder.
